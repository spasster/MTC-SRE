# Видео демонстрации

## Текущая версия

[Открыть новое видео, 4 минуты 12 секунд](demo-current.mp4). Проверено декодирование и просмотрены начало, восстановление и финальный кадр. Это дискретная запись настоящих полноразмерных кадров браузера с переменным интервалом. Фрагменты сохраняют настенные интервалы; одна явно обозначенная склейка на 3:50 пропускает 186.6 с ожидания завершения Job и возврата масштаба. Сам момент возврата не снят: в кадре показано более позднее здоровое состояние, а точное время подтверждается JSON. [Метаданные и хеш видео](results/iteration-4/demo-current-video.json). Озвучка синтетическая, Microsoft Irina.

Опыт выполнен на `3e1df76`, собственном mtc-review с двумя доступными CPU. Один поток 16 RPS предварительно измерен при двух и пяти репликах: клиентский p95 941.3 и 115.1 мс соответственно, без пропусков. Во время опыта фон выключен защищенной записью. Healer принял scale через 56.8 с и восстановил SLO до трех здоровых внешних окон через 88.2 с после инъекции, при продолжающейся нагрузке. Job завершился естественно; через 225.5 с после инъекции уже наблюдались две готовые реплики, возвращенные healer до очистки. [Полный результат](results/iteration-4/cpu-profile-spike.json), [ограничение CPU и подтвержденный возврат среды](results/iteration-4/cpu-profile-spike-environment.json).

Клиент получил 3361 ответ, все HTTP 200; пропусков нет, клиентский p95 за весь опыт 266.3 мс. Начальный минутный серверный SLO был нарушен и сохранен в результатах: суммарный клиентский процентиль не отменяет эту деградацию. Промышленный максимум и переносимость фиксированных RPS между процессорами не заявляются.

| Время видео | Содержание |
|---|---|
| 0:00 | Здоровое начало с двумя репликами |
| 0:56 | Первый снятый кадр после инъекции 16 RPS, пояснение профиля |
| 2:25 | Пять реплик и восстановленный SLO; отдельные времена API и здоровья |
| 3:50 | Обозначенная склейка к позднему здоровому кадру с двумя репликами |
| 4:12 | Конец записи |

Для повторения подготовить Prometheus на 19090 и выполнить свежий замер той же версии и контура, затем опыт. При отсутствии пригодной ступени опыт завершится с отказом. Генерацию LLM и другие нагрузки выполнять после записи.

```sh
python scripts/demo-server.py --cluster mtc
python scripts/capacity.py --cluster mtc --rates 3,9,12,15,16,18,24 --duration 120 --continue-after-failure --refine-cpu-profile --output .runtime/cpu-capacity.json
python scripts/experiment.py --cluster mtc --scenario spike --mode auto --natural-end --spike-capacity .runtime/cpu-capacity.json --spike-duration 210 --timeout 660 --output .runtime/demo-result.json
```

Открыть http://127.0.0.1:18765. Сервер слушает только localhost и показывает реальные данные; секреты и личные чаты в кадры не попадают.

## Историческая запись

[Открыть видео, 4 минуты 33 секунды](demo.mp4). Запись выполнена 7 октября 2026 по московскому времени на отдельном k3d mtc-review. Настоящие кадры браузера сохранены с интервалами настенных часов, эксперимент не ускорен монтажом. Русское пояснение озвучено Microsoft Irina, голос не принадлежит участнику команды. [Метаданные записи](results/iteration-1/demo-video.json).

На первом кадре здоровые запросы и две готовые реплики. Заранее заданные пять дополнительных запросов/с добавлены поверх трех фоновых: суммарно около 8 RPS. Healer применяет dry-run и scale до пяти, затем проверяет свежую синтетику, минутное окно и готовность Deployment. Внешний MTTR до трех здоровых измерений - 198.1 с. k6 завершился по заданной длительности 210 с; healer самостоятельно вернул две готовые реплики через 228.5 с после инъекции. Скрипт увидел этот результат до завершающей очистки. [Исходный эксперимент](results/iteration-1/demo-lifecycle.json).

| Время видео | Подтвержденное событие |
|---|---|
| 0:00 | Здоровое исходное состояние |
| 0:10 | Внесение дополнительной нагрузки |
| 1:33 | Принятие масштабирования Kubernetes API |
| 3:15 | Внутреннее подтверждение здоровья healer |
| 3:28 | Три последовательных здоровых измерения внешнего скрипта |
| 3:58 | Естественное завершение k6 и наблюдение двух готовых реплик после возврата healer |
| 4:33 | Здоровый завершающий кадр |

1051 дополнительный запрос получил HTTP 200; dropped iterations нет. Клиентский p95 за весь прогон - 354.3 мс: он включает период нарушения SLO и не заменяется здоровым минутным окном в конце. Видео доказывает восстановление, а не непрерывное соблюдение SLO.

Журнал healer в этой серии начал инцидент до новой инъекции; его MTTR 249.2 с объединяет соседние попытки и не является MTTR отдельного видео. Внешний отсчет 198.1 с начинается от текущей инъекции. Позже допуск нового опыта исправлен: [отдельный повтор](results/iteration-2/incident-isolation.json) дал 117.3 с с новым началом журнала после инъекции. Историческое внутреннее число не подменяет внешний результат.

Первый профиль 6 RPS не успел подтвердить полный цикл в короткой записи; прогон остановлен и [сохранен отдельно](results/iteration-1/demo-lifecycle-initial.json). Старое видео с ручной завершающей очисткой заменено. Секреты и личные чаты в кадры не попадают.

Видео относится к прежнему образу checkout и одной payment. После перехода на две payment и общий HTTP-клиент прежняя мощность отдельно не заявляется. Для текущей версии применяются свежие замеры и команда из первого раздела; это не точное воспроизведение исторической нагрузки. Для сравнения между запусками сохраняются профиль, параметры среды и неудачные результаты.
