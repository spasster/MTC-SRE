# Видео демонстрации

[Открыть видео, 2 минуты 29 секунд](demo.mp4). Видео записано с работающего k3d mtc-review 6 октября 2026 года. Экран читает реальные Prometheus и Kubernetes; браузеру не передаются токены. Русское пояснение озвучено синтезатором Microsoft Irina, не участником команды.

На записи дополнительная нагрузка доводит поток до 6 запросов/с. Две реплики не держат p95 < 300 мс, healer выполняет dry-run и scale до пяти. Команда API видна отдельно от последующего подтверждения здоровья. В конце скрипт эксперимента завершает k6 и возвращает исходные две реплики; этот завершающий шаг не приписывается автономному scale-down healer.

Запись начинается примерно через 57 секунд после внесения нагрузки. Полная шкала от запуска и исходные измерения находятся в [spike-auto.json](results/spike-auto.json). Внешний MTTR - 148.4 с; длительность видео и внутренний таймер от startsAt алерта не подменяют это число.

## Пояснение на записи

| Время видео | Что показано |
|---|---|
| 0:00 | Две реплики, нарушение задержки, накопление окна алерта, рабочая синтетика |
| 0:30 | Уже применён scale до пяти; принятие команды ещё не закрывает инцидент |
| 1:00 | Проверяется минутный SLO, синтетика и готовность ревизии |
| 1:30 | Задержка ниже порога, подтверждение healer и внешние здоровые измерения |
| 2:00 | Завершение эксперимента и оговорка о неуспешной нагрузке 19 запросов/с |

Для повторной демонстрации запустить port-forward Prometheus на 19090, затем в корне проекта:

```sh
python scripts/demo-server.py --cluster mtc
python scripts/experiment.py --scenario spike --mode auto --output .runtime/demo-result.json
```

Открыть http://127.0.0.1:18765 и записать экран. При другом имени кластера задать CLUSTER и одинаковый аргумент `--cluster`. Сервер доступен только локально, ничего не применяет и показывает отсутствие данных явно. Перед записью дождаться здорового SLO и исчезновения всех активных алертов. Локальную генерацию LLM во время замера отключить.
