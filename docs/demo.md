# Видео демонстрации

[Открыть видео, 4 минуты 12 секунд](demo-current.mp4). Это запись настоящего браузера. На 3:50 есть явно обозначенная склейка: пропущено ожидание конца нагрузки и возврата числа реплик. Сам момент возврата в кадр не попал, на экране уже здоровое состояние с двумя репликами.

Это локальная запись на стенде с двумя CPU, не кадры GitHub Actions. Нагрузка в видео — 16 запросов в секунду: на двух репликах клиентский p95 был 941 мс, на пяти — 115 мс. Healer поднял реплики и вернул скорость, пока нагрузка ещё шла, затем сам вернул две реплики. Прогон CI на чистом Ubuntu выбирал другую ступень, 11 запросов в секунду, и получил восстановление за 147,8 с. Оба числа относятся к своим стендам. Сводка: [architecture.md](architecture.md).

| Время видео | Содержание |
|---|---|
| 0:00 | Здоровое начало с двумя репликами |
| 0:56 | Кадр после начала нагрузки |
| 2:25 | Пять реплик и восстановленная скорость |
| 3:50 | Склейка к позднему кадру с двумя репликами |
| 4:12 | Конец записи |

Повторить на своём стенде:

```sh
python scripts/demo-server.py --cluster mtc
python scripts/capacity.py --cluster mtc --rates 3,9,12,15,16,18,24 --duration 120 --continue-after-failure --refine-cpu-profile --output .runtime/cpu-capacity.json
python scripts/experiment.py --cluster mtc --scenario spike --mode auto --natural-end --spike-capacity .runtime/cpu-capacity.json --spike-duration 210 --timeout 660 --output .runtime/demo-result.json
```

Открыть http://127.0.0.1:18765. Сервер слушает только localhost. Секреты и личные чаты в кадры не попадают.
