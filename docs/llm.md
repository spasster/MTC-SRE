# Локальный SRE-ассистент

LLM используется для отчета дежурному: `/report` разбирает текущий снимок, `/postmortem` готовит черновик по последнему инциденту в журнале healer. Это дополнительный режим кейса 2. Автоматическое восстановление выполняется правилами и работает без модели.

Оба ответа содержат четыре раздела: симптомы, действия, восстановление и следующая проверка. Текущее состояние SLO, операции и MTTR вычисляются кодом. Для этих разделов схема разрешает только точные фактические значения. Модель выбирает следующую проверку из двух кандидатов, сформированных по выбранному инциденту или текущему решению правил. Связь с источником возвращается в `selected_recommendation.basis`; полный список кандидатов также включен в ответ.

Для CPU предлагается сверить p95 и throttle до и после масштабирования, для медленного пода - UID удаленного и заменяющего подов, для потери метрик - полноту данных Prometheus. Предусмотрены отдельные проверки Redis, ревизии checkout, payment и неизвестного результата операции. Совет о payment не допускается для инцидента потери метрик без соответствующих фактов. Неверный формат, измененные факты, незавершенный ответ и рекомендация вне кандидатов дают HTTP 503.

Текущий здоровый снимок не заменяет состояние в начале прошлого инцидента. Postmortem содержит до шести операций и 12 событий с признаками сокращения. Времена начала, принятия API, подтверждения SLO и закрытия различаются. Отсутствующее подтверждение времени остается `null`. Гипотеза правил в `/report` не называется примененным действием или доказанной первопричиной.

В отдельном mtc-review настоящая Qwen2.5 1.5B проверена на [трех сохраненных инцидентах](results/iteration-2/llm-cases.json). [Результат оценки](results/iteration-2/llm-quality.json): CPU за 58.5 с, потеря данных за 33.8 с, медленный под за 35.3 с. Во всех ответах факты и MTTR сохранены, проверка связана с нужным инцидентом, `actions_applied` пуст. [Факты медленного пода](results/iteration-2/llm-pod-facts.json) относятся к новому изолированному прогону; состояние снято позже, что указано в наборе. [Образ и хеши кода модели](results/iteration-2/llm-runtime.json) фиксируют исполнявшийся код до коммита.

Это оценка ограниченного выбора из явных кандидатов. Свободный анализ первопричины, превосходство над правилом выбора и полезность на других инцидентах не доказаны. Черновик проверяет человек; `human_review_required=true`. Модель не имеет API применения и прав записи в Kubernetes.

[Postmortem через API](results/iteration-2/postmortem.json) и [текущий отчет](results/iteration-2/llm-report.json) проверены отдельно. ServiceAccount может читать demo Deployment и единственный ConfigMap healer-state. Изменение Deployment, удаление пода, изменение журнала и Lease, чтение Secret запрещены. Запросы без действующего токена запрещены. В модель передается белый список числовых метрик и полей журнала, без токенов, ID оператора, callback ID, сырых ошибок и корзины.

Промпты находятся в `healer/prompts/incident.md` и `healer/prompts/postmortem.md`. Для обоих режимов задан контекст 4096 токенов, ответ до 384 токенов, два потока CPU и HTTP-таймаут 120 секунд. Структурированная генерация описана в [документации Ollama](https://docs.ollama.com/capabilities/structured-outputs).

```sh
make llm
python3 scripts/verify-llm.py --kind report --cluster mtc --output docs/results/llm.json
python3 scripts/verify-llm.py --kind postmortem --cluster mtc --output docs/results/postmortem.json
python3 scripts/verify-llm-quality.py --cluster mtc --output docs/results/llm-quality.json
```

Для проверки качества нужен выбранный набор из не менее трех инцидентов. Скрипт последовательно повторяет генерацию настоящей моделью по сохраненным фактам, сохраняет каждый результат и сохраняет неуспех при превышении времени. Это повтор на фиксированном наборе, а не три новых живых инцидента. Генерацию запускать после измерений SLO и MTTR, чтобы расход CPU модели не менял условия нагрузки.

Ollama 0.35.1 и Qwen2.5 1.5B работают на CPU. Режим скачивает крупный образ и около 1 ГБ весов, требует дополнительных 4 ГБ RAM и диска. Для минимального `make up-linux` модель не требуется. Ссылки: [версия Ollama](https://github.com/ollama/ollama/releases/tag/v0.35.1), [API генерации](https://docs.ollama.com/api/generate), [модель](https://ollama.com/library/qwen2.5).

Исторические неудачи сохранены: [повторяющийся текст](results/iteration-1/postmortem-initial.json), [выдуманный срок](results/iteration-1/postmortem-format-initial.json), [слишком общий совет CPU](results/iteration-1/postmortem-cpu.json) и [необоснованный совет о payment](results/iteration-1/postmortem.json). Их прежний `passed` проверял HTTP/RBAC, а не качество рекомендации. В старом журнале CPU MTTR 249.2 с объединяет соседние попытки; внешний MTTR отдельного демонстрационного прогона 198.1 с сохранен отдельно. Защита фактов, изоляция новых экспериментов и ограничение рекомендаций устраняют разные причины этих ошибок.
