## Подтвержденные следующие исправления

[Управляемые воспроизведения и реальный RBAC](results/iteration-1/audit-regressions.json) дали четыре находки: ReplicaSet сравнивается по имени владельца вместо UID в возрасте ревизии и откате; чтения Kubernetes не ограничены по времени; валидный JSON с отрицательным бюджетом проходит в восстановленное состояние; healer имеет ненужные права patch/update payment. Чужие Deployment и настоящий ConfigMap в проверках не повреждались.

Пятый дефект найден по живому журналу: соседние эксперименты объединили начало инцидента. Поэтому внутренние 249.2 с в postmortem не заменяют внешний MTTR 198.1 с отдельного нового прогона. Новый эксперимент должен допускаться только после закрытого состояния healer. Критерии приемки пяти задач находятся в [iteration-2.md](iteration-2.md).

## Пробелы ТЗ и границы

Пункт 5 ТЗ требует удержания SLO при хаосе. Текущий полный сетевой разрыв и начальная часть CPU spike его нарушают. Восстановление после сбоя подтверждено, непрерывное соблюдение SLO во всех воздействиях - нет. Для следующей цели нужны заранее определенная область ограниченного отказа, устойчивость сервиса и отдельная положительная проверка SLO; полные отрицательные опыты сохраняются.

Модель дважды дала плохой текст: [повторы](results/iteration-1/postmortem-initial.json) и [выдуманный срок](results/iteration-1/postmortem-format-initial.json). После этого фактические разделы ограничены enum. Последняя рекомендация назвала трейс и логи payment, но связь с выбранным инцидентом потери метрик не подтверждена. Нужна оценка нескольких инцидентов с критериями конкретности и опоры на данные. HTTP 200 и корректный JSON не являются такой оценкой.

30-дневный SLO, точный максимум RPS, минимальные ресурсы, промышленная HA и средняя скорость человека не доказаны. Baseline задает задержку 30 секунд после firing. CPU/RAM мощности измерены для контейнеров checkout; дополнительные ступени сняты отдельной серией. Неудачные попытки CI, нагрузки и модели сохранены.

Имена и роли четырех участников подтверждены владельцем в [team.md](team.md). Индивидуальный опыт и исторический вклад по коммитам не выдуманы. Полноценные rsyslog/auditd проверены на свежем Ubuntu CI; Windows использует отдельный Docker Engine в WSL. Слияние и промышленное развертывание не выполнялись.
