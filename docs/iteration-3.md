# Третья итерация по подтвержденным дефектам

Документ сохраняет историю дополнительного аудита. Все пять исправлений включены в рабочую ветку. Прежнее намерение запускать следующие цели отменено указанием пользователя 7 октября 2026; текущая приемка находится в [audit.md](audit.md).

Основание - [управляемые воспроизведения](results/iteration-2/audit-regressions.json) на 36a284a и [отказ предыдущего Ubuntu CI](results/iteration-2/ci-prior/run.json). Проверки SDK и состояния выполнены вне кластера; настоящие объекты не изменялись. Исправления подготовлены в отдельном checkout во время CI. После его отказа они внесены в fix/sre-case-completion перед следующим полным запуском, каждый отдельным русским коммитом. Это выполненный дополнительный цикл аудита текущей цели; дальнейшая приемка описана в [audit.md](audit.md).

| Задача | Подтверждение | Критерий приемки |
|---|---|---|
| 1. Проверять управляющий контроллер | ReplicaSet со ссылкой checkout `controller=false` и другим управляющим контроллером принят для телеметрии, возраста и предыдущего шаблона | Вся цепочка Deployment -> ReplicaSet -> Pod требует UID и `controller=true`. Обычная ссылка владельца, другой контроллер и отсутствие управляющей ссылки запрещают выбор; управляемая цепочка продолжает работать |
| 2. Проверять смысл ожидающего подтверждения | Снимок с diagnosis=redis и action=rollback восстановлен, хотя поля противоречат друг другу | До восстановления и записи допускаются только redis/restart_redis/redis и bad_release/rollback/checkout. Противоречие не меняет работающий процесс. Повторная проверка актуальных метрик перед API сохраняется; ее обход в аудите не доказан |
| 3. Соблюдать срок ожидания эксперимента | Чтение закончено на шестой секунде при сроке пять секунд, но закрытый инцидент принят как успех; cmd не ограничивает subprocess | Общая оболочка cmd имеет конечное время выполнения. Чтение в цикле получает оставшийся бюджет; после срока успех не возвращается и инъекция не запускается. Сбой и превышение времени сохраняются как неуспешный исход |
| 4. Переносить конфликт проверки scale без потери результата | Предыдущий CI остановился на 409 Conflict в уменьшении масштаба; scale-guard.json остался пустым | Проверочный скрипт повторяет только отклоненный CAS с неизменными UID, generation и ожидаемым числом реплик, в конечном бюджете. Чужое изменение останавливает повтор. Очистка имеет независимый исход; итоговый JSON сохраняется и при конфликте или неудаче |
| 5. Проверять свежесть после окончания сбора | Последовательный сбор занимает больше 45 секунд, но возраст считается относительно общего времени в начале; получен автоматический scale по устаревшему снимку | Длительность сбора ограничена и включена в итоговый возраст метрик и синтетики. Слишком старый или неполный снимок не разрешает действие и восстановление. Общий момент оценки Prometheus сохраняется для согласованности данных |

Ссылка `controller=true` обозначает управляющий контроллер согласно [Kubernetes OwnerReference](https://kubernetes.io/docs/reference/kubernetes-api/definitions/owner-reference-v1-meta/). UID обычного владельца нужен для другой связи и сам по себе не подтверждает управление.

Гипотеза об уменьшении чужого масштаба при отсутствующем scale_owner отвергнута: `_scale_to_baseline` уже запрещает такую операцию. Не добавляются задачи без воспроизведения. Месячная история SLO и опыт участников остаются внешними данными; короткий CI не заменяет их.

## Исправления и проверка

| Пункт | Коммит | Результат |
|---|---|---|
| 1 | 0f14262 | Обычная ссылка владельца не выбирает ReplicaSet, возраст, под или шаблон отката |
| 2 | 1837c32 | Противоречивое подтверждение запрещено до изменения глобального состояния и записи |
| 3 | b312a49 | Оболочка cmd имеет конечный таймаут; успешное чтение после срока не допускает инъекцию; ошибка очистки сохраняет JSON |
| 4 | bcd61e0 | Только отклоненный CAS повторяется до трех попыток; изменение оператора сохраняется, отказ очистки не теряет итог |
| 5 | 218ff47 | Сбор допускается в бюджет 20 секунд и проверяется до/после каждого вызова; итоговые возраста включают сбор, старый снимок запрещает действие и восстановление |

Все пять исходных воспроизведений повторены: [audit-fixes.json](results/iteration-3/audit-fixes.json), passed=true. Это управляемая проверка SDK, времени и процесса, а не отдельный живой инцидент. На 24c22ec прошли 263 теста healer. Таймаут SDK остается 5 секунд; составной вызов завершается в своем конечном бюджете, а ответ после общего срока сбора всегда отвергается. Жесткое прерывание всех вложенных вызовов ровно на двадцатой секунде не заявляется.

[Следующий аудит](results/iteration-3/audit-regressions.json) подтвердил две новые ошибки и два прямых процесса без таймаута, которые обходят cmd. Затем [настоящий повтор make apps](results/iteration-3/image-update-regression.json) обнаружил старый образ payment в готовой ревизии. Критерии четырех выполненных задач описаны в [iteration-4.md](iteration-4.md); заключительная приемка приведена в [audit.md](audit.md).
