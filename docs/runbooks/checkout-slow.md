# CheckoutSlow

Предупреждение: p95 GET /work за окно 1 минута выше 300 мс и держится 30 секунд. Ответственный - дежурный участник команды; персональный список заполняется владельцем проекта.

1. На дашборде «Checkout SLO» проверить поток запросов, синтетику и ошибки. Без данных восстановление не подтверждается.
2. На дашборде «Инцидент» сравнить p95 и throttle каждого пода. Один под минимум втрое медленнее остальных, свежие данные и throttle ниже 0.4 - healer выполняет dry-run и удаляет этот под.
3. Если все поды ограничены CPU, healer увеличивает checkout до пяти реплик. Если пять реплик не восстановили SLO, требуется оператор; дальнейшее автоматическое увеличение запрещено.
4. По exemplar перейти в Tempo и логи Loki. Проверить длительность payment и Redis, готовность Deployment и события Kubernetes. Готовые поды не доказывают исправность зависимостей.
5. После действия дождаться здоровых метрик, свежей синтетики и текущей готовой ревизии. Принятие команды API не закрывает инцидент.

Resolved может поступить позже из-за окна метрик. Возврат к двум репликам выполняется только после завершения нагрузки, проверки здоровья и только для масштабирования, выполненного healer. Ошибка scale-down оставляет повторную попытку в очереди.

В учебном контуре: `sh chaos/inject.sh slow-pod` или `sh chaos/inject.sh spike`. Снять эксперимент: `sh chaos/inject.sh clear`. Ждать исчезновения всех активных алертов перед следующим запуском.
