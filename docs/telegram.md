# Выделенный бот и права операторов

Живые проверки 7 октября 2026 по московскому времени: `docs/results/iteration-1/telegram-approve.json` подтверждает кнопку отката и восстановление SLO; `telegram-reject.json` подтверждает отказ от рестарта Redis без изменения Deployment. Нового стороннего участника в чат не добавляли: запрет чужому оператору, повторные и просроченные запросы проверены управляемыми тестами. При обнаруженной в ходе проверки несогласованности долей метрик выполнено отдельное исправление, описанное в audit-snapshot.md.

Для этой итерации создан отдельный тестовый бот `@mtc_sre_iter_20261006_bot` и его личный диалог. Существующие группы не изменялись. Токен, ID чата и ID оператора размещены в Kubernetes Secret `heal/telegram`; в репозитории этих значений нет.

Воспроизводимая настройка нового окружения: `python3 scripts/configure-telegram.py --cluster mtc --chat-id <ID_ЧАТА> --operators <ID_ОПЕРАТОРА>`. Токен вводится скрыто. После `make observability CLUSTER=mtc` Alertmanager получает Secret и маршрут уведомлений, а `kubectl rollout restart deployment/healer -n heal` обновляет настройки процесса. Без заполненного списка операторов кнопки управления не отправляются.

Оператор определяется по `callback_query.from.id`, полученному от Bot API. Проверяются разрешенный чат, человек вместо бота, числовой ID в `TELEGRAM_ALLOWED_USER_IDS`, уникальный запрос подтверждения, TTL, актуальность метрик и UID/generation/revision Deployment. Само участие в группе не разрешает действие. Новый участник добавляется владельцем явно через Secret.

Журнал содержит запрос подтверждения, принятое или отклоненное решение и отказ чужому оператору. Для сопоставления применяются сокращенные SHA-256 от ID оператора и запроса; исходные ID не публикуются в отчетах. Это псевдонимы, а не гарантия необратимой анонимизации. Доступ к журналу ограничен RBAC.

Перед подтверждением опасного действия производится серверный dry-run. Подтверждение сообщает только о принятой API команде; отдельное сообщение о восстановлении появляется после проверки запросов, синтетики и текущего rollout. Ошибка Telegram не означает успешное действие.
