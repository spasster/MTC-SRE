# Обновление и проверка локальных образов

`make images` собирает checkout, payment и healer. При установке `make apps`, `make observability` и `make llm` создается локальный тег вида `payment:local-<SHA-256>` по идентификатору собранного образа Docker. Тег импортируется в выбранный k3d и используется в шаблоне Deployment. Изменение образа меняет шаблон и запускает rollout; прежний тег `:dev` в рабочем Deployment больше не скрывает старые поды.

Перед применением код образа сверяется с исходниками: Python-файлы приложения и requirements.txt, для healer также правила и промпты. Если образ собран до изменения кода, команда завершается отказом до записи Deployment. Сначала нужно выполнить `make images`, затем установку нужного компонента. Отдельный образ, заданный оператором, автоматически не заменяется.

Обновление существующего Deployment передает UID и resourceVersion. Только явно отклоненный Conflict допускает до трех попыток; перед повтором проверяются исходные UID, generation и полный spec. Изменение другим участником или неизвестный ответ API прекращают запись. Первое создание не повторяется после неопределенного ответа.

Готовность дополняется проверкой всех текущих реплик: связей контроллеров Deployment -> ReplicaSet -> Pod, текущей ревизии, фактического imageID и SHA-256 кода каждого пода. UID перечитывается после проверки кода. Старый готовый образ и под, замененный во время проверки, не дают успешный результат. Повтор установки с тем же образом сохраняет шаблон; отсутствие лишнего rollout проверяется отдельно по generation и UID подов.

```sh
make images CLUSTER=mtc
make apps CLUSTER=mtc
python scripts/local-images.py --cluster mtc --component checkout payment healer --verify-only --output .runtime/runtime-images.json
```

Режим `--verify-only` проверяет уже установленные компоненты и не изменяет Kubernetes. Итоговый JSON сохраняется и при отказе; внешние ответы, аргументы команд и закрытые данные в него не включаются. Полный CI выполняет такую проверку до инъекции хаоса.

Эксперимент повторно импортирует закрепленный тег healer перед его запуском после baseline, затем проверяет фактические образы и код до инъекции. Серия мощности импортирует исходный закрепленный тег перед возвратом healer. Это предотвращает загрузку случайного содержимого `:dev` при перезапуске. Владение очисткой и допустимость восстановления числа реплик проверяются отдельно от идентичности образа.
